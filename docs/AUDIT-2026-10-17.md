## 3. The "Moving file failed … different disk drive" error

**Diagnosis (confirmed from `Logs/Editor.log`).** Unity saves editor preferences by
writing a temp file in the project's `Temp/` folder (drive **E:**) and then *moving*
it to `C:\Users\yo5on\AppData\Roaming\Unity\Editor-5.x\Preferences\…` (drive **C:**).
A plain move (rename) cannot cross drives on Windows, so the save fails:
- 10× for `Preferences/Overlays/CanvasesSaveData.asset` (Scene-view overlay layout),
- on exit for `Preferences/Layouts/current/default-6000.dwlt` (window layout); "Force
  Quit" was then pressed, ending the editor with a fatal error.

Only **editor UI preferences** are affected (window/overlay layout), not project data.
`Level1.unity` was saved (20:31) before the forced quit. Nothing in the project's
configuration causes this; it is the drive layout (project on E:, user profile on C:)
combined with this editor version's save routine. Not reproduced in batch-mode builds.

**Safe options (none applied):**
1. Keep working, and when the dialog appears choose the non-quit option; save scenes
   (Ctrl+S) before closing the editor. Lowest risk; layouts may not persist.
2. Recommended long-term: keep the project on the **same drive as your user profile**
   (e.g. a clone in `C:\Users\yo5on\Projects\MazeRunner`; C: has ~92 GB free). Needs
   your approval — it moves your working copy.
3. Test whether the project's own editor version **6000.5.1f1** behaves the same (the
   error was seen with 6000.6.5f1).
Not recommended: redirecting AppData or changing Windows settings.

## 6. Performance and build size

- Web build: ~16.5 MB transferred (data 7.2 MB, wasm 9.2 MB, gzip). The first scene
  (MainMenu) carries 3.0 MB compressed / 9.1 MB uncompressed of shared data,
  including all `Resources/` content.
- Biggest easy win: remove TMP **Examples & Extras** (its `Resources` are shipped).
- Compress `MazeRunner_RuinPillar.png` (currently uncompressed) if it stays.
- Audio: all clips are Vorbis 100 % / Decompress On Load; the only large one is
  `Level1.mp3` (573 KB). On WebGL Unity re-encodes for the browser, so savings are small.
- Scripts: no `Find`/`GetComponent`/allocations in per-frame code except the fixed
  `CameraFollow` case. `EnemyTracker` uses `FindObjectsByType` once per scene load.
- Web page: 20 event listeners, each registered once (no duplicates); JS syntax OK.
